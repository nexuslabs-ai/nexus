# Nexus fixes the engine, not the plumbing

**Nexus UI answers the theming half of the design-system complaint list better than any library examined, and does not yet answer the delivery half.** The most persistent theming pains of 2024–2026 are three. shadcn/ui caps theming at color variables plus one radius. MUI users have asked for a global density switch since 2018. Every mainstream library makes teams hand-wire workarounds to change a brand color at runtime. Nexus addresses all three with one appearance object. A single call derives every color, hover, pressed and dark-mode value from any brand color, and density, corners, elevation and stroke are runtime tokens. CI checks text contrast across 3,535 brand, surface and contrast combinations in both modes, and a CI test keeps every Nexus rule inside `nx:` classes and `--nx-*` variables, so Nexus can sit beside MUI or shadcn without changing a host style. The pains shadcn spent 2026 solving are where Nexus falls behind: updating edited copies (Nexus says "paste the newer version over yours"), installing from a registry ("Coming soon"), giving agents context and an install path (no MCP server or skill), and choosing a primitive layer (Radix only, after shadcn made Base UI its default). Accessibility splits the same way. The APCA gate and outline focus rings are stronger engineering than shadcn's unchecked defaults. But Nexus runs no WCAG 2 check in a market where every law and procurement form measures WCAG 2, its default success and warning badges fail WCAG 2 at 3.35:1 and 3.96:1, and a repo rule bans honoring the OS reduced-motion and forced-colors signals. Multi-framework teams get a framework-agnostic engine but no non-React components. That is the "tokens shared, components per framework" model practitioners call necessary but not sufficient. Two limits frame every verdict. Reddit, X and LinkedIn could not be read, so the developer voice here comes from Hacker News, GitHub, vendor docs and blogs. And Nexus has no public reception to weigh (2 GitHub stars, about 18 npm downloads a week), so these verdicts test its design against the complaints rather than report what users think of it.

## Twelve recurring pains, three clean Nexus wins

The complaints in this report recur across years and libraries but rarely go viral on any single thread. The runtime brand-color question on Mantine drew **1–2 upvotes** per post ([mantinedev #7420](https://github.com/orgs/mantinedev/discussions/7420)), and the per-tenant Tailwind thread has a handful ([tailwindlabs #3100](https://github.com/tailwindlabs/tailwindcss/discussions/3100)). The loud threads are about shadcn itself: "Shadcn/UI now defaults to Base UI instead of Radix" reached **282 points and 165 comments** ([HN 48791328](https://news.ycombinator.com/item?id=48791328)), and "The Overcomplexity of the Shadcn Radio Button" reached **528 points and 326 comments** ([HN 46688971](https://news.ycombinator.com/item?id=46688971)). The signal is breadth and persistence, not volume. Nexus itself has no footprint to measure against that: on 2026-10-20 its repo had **2 stars and 1 fork** ([GitHub](https://github.com/nexuslabs-ai/nexus)), `@nexus_ds/core` had **18 downloads in the prior week and 1,587 in a year** ([npm last-week](https://api.npmjs.org/downloads/point/last-week/@nexus_ds/core), [npm last-year](https://api.npmjs.org/downloads/point/last-year/@nexus_ds/core)), and the team's own growth issue lists the Show HN, Reddit and Product Hunt launches as unchecked to-dos ([issue #868](https://github.com/nexuslabs-ai/nexus/issues/868)).

|---|---|---|---|

## Theming stops at color elsewhere, and Nexus makes every other axis a setting

### The complaint: one radius, no density, and restyles that rewrite code

shadcn/ui's official theme surface is semantic color variables plus a single base `--radius`, with spacing, shadows and type left out ([shadcn/ui Theming](https://ui.shadcn.com/docs/theming)). When a shadcn theme editor launched on Hacker News (**136 points, 41 comments**), a user asked for "a different border radius on buttons or margin on labels" and "more variance in the actual shapes and looks of things." The editor's own author answered that "you're limited to adjusting the css variables they provide" ([HN 45706487](https://news.ycombinator.com/item?id=45706487)). That cap feeds the louder "shadcn sameness" complaint. shadcn conceded it in December 2025: "all apps started looking the same. I guess the defaults were a little too good. My bad" ([shadcn changelog](https://ui.shadcn.com/docs/changelog/2025-12-shadcn-create)). Users still write that "every app that use shadcn use 100% same" ([HN 48792287](https://news.ycombinator.com/item?id=48792287)). A sharper critic argues that "a UI for toggling border radius and colour palettes isn't going to help this," because most projects never leave the defaults ([HN 47985939](https://news.ycombinator.com/item?id=47985939)). shadcn's answer was eight regenerated visual styles, whose config "rewrites the component code to match your setup" ([shadcn changelog](https://ui.shadcn.com/docs/changelog/2025-12-shadcn-create)). Community tools such as tweakcn (**10.5k stars**) still edit only the variables shadcn exposes ([jnsahaj/tweakcn](https://github.com/jnsahaj/tweakcn)).

Density is the most clearly recurring beyond-color request, and the longest unmet one. MUI users asked for compact display in 2018 ([mui #12623](https://github.com/mui/material-ui/issues/12623)), a global dense option in 2019 ([mui #15988](https://github.com/mui/material-ui/issues/15988)), and one place to "scale all the components and font sizes" in 2024. A maintainer replied: "What we have today feels not really usable" ([mui #41579](https://github.com/mui/material-ui/issues/41579)). MUI's June 2026 RFC still describes its density support as **"a per-component workaround, not a density system"** that covers 13 components ([mui #48746](https://github.com/mui/material-ui/issues/48746)). shadcn shipped density as Rhea, a separate compact style. It rejected a runtime switch on purpose: `--spacing` is a multiplier, so changing it would redefine what `p-2` and `w-4` mean across the app ([shadcn changelog: Rhea](https://ui.shadcn.com/docs/changelog/2026-05-rhea)). A shadcn-svelte contributor put the constraint plainly: "size and spacing can't be controlled by the root css" ([shadcn-svelte #2463](https://github.com/huntabyte/shadcn-svelte/issues/2463)). A community fork exists only to add compact and comfortable densities ([alexgorbatchev/shadcn](https://github.com/alexgorbatchev/shadcn)).

### The complaint: changing a brand color at runtime takes workarounds everywhere

Runtime brand color for white-label and multi-tenant apps takes a workaround in every mainstream library. Mantine's maintainer told a user that "To update values dynamically you need to use state in react, properties assignment won't work." The user's fix was a Zustand store plus a generated palette ([mantinedev #7420](https://github.com/orgs/mantinedev/discussions/7420)). MUI's `createTheme` rejected CSS variables with "MUI: Unsupported `var(--custom-css-var)` color" ([mui #35395](https://github.com/mui/material-ui/issues/35395)). A Panda maintainer said the engine behind Chakra v3 "is not trying to be a hybrid (static+dynamic) solution" ([chakra-ui/panda #796](https://github.com/chakra-ui/panda/discussions/796)). The hidden cost is derivation, not wiring. A typical multi-tenant Tailwind write-up sets only the tenant's 500 shade. It leaves hover on a global 600, handles dark mode in a separate media query, and still flashes on load because the theme arrives after a client fetch ([dev.to](https://dev.to/uaslimcreate/building-a-custom-tailwind-css-theme-system-for-multi-tenant-branding-dynamic-colors-without-6pk)). Radix Themes users find accent variables that don't follow light and dark mode ([radix-ui/themes #731](https://github.com/radix-ui/themes/issues/731)). The palette tools teams reach for, Radix's generator, Mantine's generator and Material color utilities, all produce static scales that someone must still map to semantic roles. Multi-brand is not niche at the organization level. In zeroheight's 2026 survey of 147 practitioners, **29% maintain multiple, entirely different design systems and 22% run a parent system with child systems** ([zeroheight 2026](https://report.zeroheight.com/)).

### What Nexus ships, and where it stops

Nexus answers both complaints from the same object. Its appearance state carries `brandColor`, `surfaceTone`, separate light and dark contrast settings, **six density modes, five corner modes, five elevation modes and three stroke widths**, plus font and preference fields ([appearance-model.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/appearance-model.ts#L28-L144)). `deriveTheme` and `themeToCss` turn it into `:root` and `:root.dark` blocks ([derive-theme.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/derive-theme.ts#L464)). A first-paint script restores the saved appearance before the app loads. The docs promise: "The page looks right with JavaScript off, and a live theme change needs no rebuild" ([tokens.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/foundations/tokens.mdx#L67-L81)). Light and dark come from one call, so the accent-drift failure in Radix #731 can't occur by construction. Density is a `[data-density]` attribute on any ancestor that swaps the `--nx-spacing-*` scale ([nexus.css](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/tailwind/nexus.css#L518-L521)). That answers MUI's eight-year request and the compact-region-in-a-comfortable-page case. The HN request for pill buttons beside square inputs has a documented recipe: set `--nx-radius-base` on a wrapper and only buttons read it ([overrides.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/theming/overrides.mdx#L38-L41)). The deepest advantage is structural. A Nexus re-theme never touches a copied component file, while shadcn's styles and presets rewrite component source, which collides with local edits.

The limits are real and specific. Nexus's density makes exactly the tradeoff shadcn refused: `nx:p-2` means different pixels at different densities. Nexus confines that to its own `nx:` utilities, so host Tailwind classes keep their meaning, but the objection should be answered up front rather than discovered. Brand and color are page-global. The docs say plainly that only density, radius, shadow and border width scope to an element and "The other fields apply to the whole app" ([overrides.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/theming/overrides.mdx#L29-L36)). A per-subtree theme root was closed ([issue #798](https://github.com/nexuslabs-ai/nexus/issues/798)), so two tenants on one page, or an embedded widget with its own brand, are out of reach today. An open issue titled for a "scoped-appearance" core release suggests this may change ([issue #797](https://github.com/nexuslabs-ai/nexus/issues/797)). Scoped overrides also miss portals: "A popover or menu that renders in a portal sits outside your wrapper, so it doesn't get the override" ([overrides.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/theming/overrides.mdx#L102-L103)). That is the same failure the community is actively patching elsewhere ([json-render PR #397](https://github.com/vercel-labs/json-render/pull/397)). "Motion" is listed as a setting in Nexus's pitch, but it ships one token mode and an on/off reduce toggle, with no motion field to match density or corners ([variables.css](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/tailwind/variables.css#L345-L356)). On sameness, more axes give teams more ways out, but Nexus's defaults face the same inertia the HN critic described, and its components are shadcn-shaped.

## Nexus can join a live app without touching it, in a prefix developers dislike

### The complaint: two systems on one page break each other

The most reported coexistence failure is Tailwind's Preflight reset overwriting another library's element styles. A canonical thread shows MUI buttons going transparent inside a Tailwind template. Its accepted fix is a hand-copied reset with the button rules removed ([tailwindlabs #11290](https://github.com/tailwindlabs/tailwindcss/discussions/11290)). A Next.js team planning an MUI-to-shadcn move found that disabling Preflight "seems to solve conflicts, but then the styles with tailwind crash," and asked, "I will have to put the prefix tv on each style?" ([mui #44333](https://github.com/mui/material-ui/issues/44333)). A January 2026 micro-frontend thread reports leaks in both directions. The remote's "Tailwind `Preflight` (reset) is leaking out" and stripping the Laravel host's buttons, while the host's aggressive globals leak in. The team can't use Shadow DOM "because we rely on several external libraries" ([tailwindlabs #19578](https://github.com/tailwindlabs/tailwindcss/discussions/19578)). Runtime CSS-in-JS adds an injection-order fight. MUI's own Tailwind v4 guide requires `enableCssLayer` and an explicit `@layer theme, base, mui, components, utilities;` order ([MUI docs](https://mui.com/material-ui/integrations/tailwindcss/tailwindcss-v4/)).

The sharpest incremental-adoption complaint is a missing upgrade path. Chakra's maintainers answered "We do not support a gradual v2 plus v3 install. Migrate fully to v3." A user replied that "It's easier migrate from Chakra v2 to shadcn than v3" ([chakra-ui #9853](https://github.com/chakra-ui/chakra-ui/discussions/9853)). The top answer to "How to upgrade to v3 incrementally?" was "You can't" ([chakra-ui #9184](https://github.com/chakra-ui/chakra-ui/discussions/9184)). MUI users are frustrated that Pigment CSS, its RSC-compatible engine, stalled. The repo is labelled "Alpha phase, currently, on hold" ([mui/pigment-css](https://github.com/mui/pigment-css)), and one user said "The whole pigment css saga has been disappointing" ([mui #45759](https://github.com/mui/material-ui/issues/45759)). Teams that migrate anyway do it page by page and build their own bridges. One MUI-to-shadcn team found "Theme tokens didn't map 1:1" and wrote a bridge that "let us migrate components incrementally" ([dev.to](https://dev.to/ashishxcode/mui-to-shadcn-7-pitfalls-we-hit-and-the-fix-for-each-3eh)).

### What Nexus ships for coexistence

This is Nexus's most rigorously engineered answer. Nexus imports Tailwind's theme and utilities under `prefix(nx)` with no Preflight. A unit test compiles the consumer CSS with every class the components use and fails on any selector outside `nx:` classes or variable scopes, and on any global declaration that isn't `--nx-*` ([generated-css-scope.test.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/generated-css-scope.test.ts#L5-L177)). The change was deliberate. Before it, adding Nexus **changed 27 host styles** in the practice app, through Preflight, `*`/`body` rules and 107 unprefixed color aliases ([issue #794](https://github.com/nexuslabs-ai/nexus/issues/794)). Now the shadcn-app, mui-app and shadcn-package examples each report that adding Nexus **changes 0 of the host's styles** ([examples/README.md](https://github.com/nexuslabs-ai/nexus/blob/61e1776/examples/README.md#L23-L48)). That is the "namespaced output, no global reset" property every workaround in #11290 and #19578 is trying to recreate. Overlay layers are variables the host can raise; the MUI example lifts them to 1600–1800 ([mui-app nexus.css](https://github.com/nexuslabs-ai/nexus/blob/61e1776/examples/mui-app/src/nexus.css)). Nexus toasts use their own toaster id so a host toaster never shows them ([core CHANGELOG](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/CHANGELOG.md)). One `.dark` class drives both systems ([install.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/install.mdx#L400-L401)). Styling is static CSS with no runtime injection, which sidesteps the Pigment and styled-components pressure. Radix-based parts still need `'use client'`, as shadcn's do.

The gaps sit on the other side of the boundary. The "0 changed styles" figures come from a script the team runs by hand, and wiring the examples into CI is still open ([issue #798](https://github.com/nexuslabs-ai/nexus/issues/798)). The check measures only outbound changes. Inbound bleed is untested. Tailwind v4 puts utilities in a cascade layer, and "Styles that are not defined in a layer always override styles declared in named and anonymous layers" ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer)). So an unlayered host rule, such as Bootstrap Reboot or a CssBaseline without `enableCssLayer`, can still restyle a Nexus component. No example covers a Bootstrap host or a Tailwind v3 host. Nexus also brings Tailwind 4 into apps that never had it: "adding Nexus brings Tailwind into the app for the first time" ([mui-app README](https://github.com/nexuslabs-ai/nexus/blob/61e1776/examples/mui-app/README.md)). Hosts on Tailwind end up with "two Tailwind builds, one prefixed and one not" ([install.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/install.mdx#L394-L395)). An open Nexus dialog blocks pointer events outside itself, so host popups inside it need `disablePortal` ([install.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/install.mdx#L432-L433)). Most important for migrations, nothing maps an MUI theme or shadcn variables to `--nx-*`. Migrated pages share only the dark switch with the old ones and look different until someone re-themes by hand. That is exactly the bridge teams currently build themselves.

### The prefix splits two ways

Tailwind v4 moved the prefix into variant position, so `tw-bg-x` became `tw:bg-x`, and users resent it. One called the new form "confusing, harder to read and lessens the usability of it" ([tailwindlabs #15807](https://github.com/tailwindlabs/tailwindcss/discussions/15807)). The main thread (**25 votes** on the opening post) says "the readability of the 'tw:' is worse than the 'tw-' prefix." GitLab, with **"20,000+ CSS classes with a `gl-` prefix,"** is still on v3. Bitwarden is weighing the same choice, and another team wrote that "Upgrading to v4 is currently a blocker for us." A maintainer's only reply was a question ([tailwindlabs #16046](https://github.com/tailwindlabs/tailwindcss/discussions/16046)). Nexus splits this complaint cleanly. The enterprise cost, prefixing a host's own thousands of classes, never arises, because only Nexus's own classes carry `nx:`. But every Nexus class uses the variant-position prefix users dislike, and it stacks long role names on top (`nx:hover:bg-primary-background-hover`), combining class length and prefix-as-variant. In a new app the docs are blunt: "`nx:flex` works, `flex` does not… Tailwind's default colors are gone" ([install.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/install.mdx#L70-L74)). The merge-tooling pain is handled. Nexus's `cn()` ships tailwind-merge preconfigured for the `nx` prefix and its custom class groups ([utils.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/react/src/lib/utils.ts)). Editor IntelliSense across two Tailwind entries is undocumented.

## shadcn's 2026 tooling has overtaken Nexus on updates, primitives and agents

### Updating edited copies: Nexus offers what shadcn offered in 2023

Updating an edited copy is the oldest copy-and-own complaint. A 2023 issue explained that `diff` shows how your file differs from upstream, not what upstream changed, and asked for a 3-way merge. It got no maintainer reply and was auto-closed as stale ([shadcn #2121](https://github.com/shadcn-ui/ui/issues/2121)). A 2024 bug, where `diff` printed "No updates found." for an edited component, is still open with 13 👍 ([shadcn #5427](https://github.com/shadcn-ui/ui/issues/5427)). Vercel's own course admits that the wrap-it workaround "effectively doubles the component design system size and makes the ownership concept redundant" ([Vercel Academy](https://vercel.com/academy/shadcn-ui/updating-and-maintaining-components)). The Tailwind v4 upgrade bundled framework and design changes. In a **135-comment** discussion, users reported that "All the animations for the open and closing states of popovers broke" and that Select dropdowns "started rendering fully transparent" ([shadcn discussion #6714](https://github.com/shadcn-ui/ui/discussions/6714)). Multi-app teams see copies diverge. One author found four apps that had "drifted: 17, 14, 15, and 11 primitives" ([daniel-miller/design](https://github.com/daniel-miller/design)).

shadcn has since moved, though not to deterministic tooling. CLI v4 tells users to run `--diff` "Or ask your agent: 'check for updates from @shadcn and merge with my local changes'" ([shadcn CLI v4](https://ui.shadcn.com/docs/changelog/2026-03-cli-v4)). For the Radix-to-Base UI move it shipped an agent skill instead of a codemod, because "A codemod handles the components you never touched and breaks on the ones you did" ([shadcn changelog](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)). Critics call that a regression: "now there is an upgrade ai agent for something that should just be ticking up a version number" ([HN](https://news.ycombinator.com/item?id=48791684)). Defenders make the strongest pro case. After MUI's API-upending majors, "upgrades are now easy; we can upgrade a single component" ([HN](https://news.ycombinator.com/item?id=48794963)). One even calls a shadcn upgrade "nothing more than a stranger's PR to my UI kit" ([HN](https://news.ycombinator.com/item?id=48796142)). shadcn also moved shared plumbing back into packages, `cn` and `shadcn/tailwind.css` among them ([shadcn changelog: cn](https://ui.shadcn.com/docs/changelog/2026-09-cn)). That is a tacit admission that some layers should update centrally.

Nexus sits behind this. Its update instruction is "To update one, paste the newer version over yours" ([introduction.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/introduction.mdx#L16-L18)). It has no version stamp, no diff and no dry run. The registry's install tab reads "Coming soon" ([ComponentInstallation.tsx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/app/_components/ComponentInstallation.tsx#L61-L72)). Its planned scope is explicit: "No automatic overwrite and no 3-way merge" ([issue #798](https://github.com/nexuslabs-ai/nexus/issues/798)), with a custom CLI out of scope ([issue #794](https://github.com/nexuslabs-ai/nexus/issues/794)). Setup takes four steps and about a dozen copied files before the first component ([install.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/install.mdx#L11-L184)). Nexus stays on 0.x and ships breaking changes as minor bumps. Version 0.6.0 was marked breaking and 0.7.0 changed defaults ([core CHANGELOG](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/CHANGELOG.md)). So the churn complaint is sharper here, not softer.

Nexus does land the half shadcn backed into. Its engine is a versioned npm package and its components are copies, so token, color and contrast fixes arrive through `npm update @nexus_ds/core`. Tokens can't drift between apps because one function generates them. Because restyling lives in tokens, a theme change and a local component edit never collide. Component fixes still need manual re-pasting. On the primitive layer Nexus is exposed. shadcn made Base UI the default in July 2026, citing "6M+ weekly downloads" and new projects picking it "2 to 1" over Radix ([shadcn changelog](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)), and added React Aria as a first-class base ([shadcn changelog](https://ui.shadcn.com/docs/changelog/2026-07-react-aria)). Radix's co-creator, now at Base UI and self-described as biased, called Radix "a liability" ([X](https://x.com/colmtuite/status/1935629877069172861)). Nexus depends on **28 separate `@radix-ui/react-*` packages**, not even the unified `radix-ui` package, with no alternative base ([packages/react/package.json](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/react/package.json)). Its own docs concede the ecosystem gap: "Most community blocks and registries target shadcn/ui's token names" ([introduction.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/introduction.mdx#L72-L76)).

### Agents: Nexus lints the right mistakes but has no way in

The core AI complaint is a triad: agents guess, the guess is a stock Tailwind or shadcn value, and the rules file that should have stopped it gets skipped. Storybook's MCP launch says "Agents don't know anything about your components so they make up slop" ([Storybook](https://storybook.js.org/blog/storybook-mcp-for-react/)). A Figma Make test found invented colors, hardcoded `#FFFFFF` and off-scale padding, and concluded: "tokens were documentation, not constraints" ([OverlayQA](https://overlayqa.com/blog/ai-design-system-drift/)). A Claude Code bug titled "ignores CLAUDE.md rules repeatedly despite acknowledgment" was closed as not planned ([claude-code #19635](https://github.com/anthropics/claude-code/issues/19635)). Prose docs are expensive context. Indeed's benchmark across **1,056 prompts** found Markdown cost about **30,000 tokens per query**, while structured JSON used about 80% fewer ([Into Design Systems](https://www.intodesignsystems.com/blog/design-system-not-ready-for-ai-agents)). The fix practitioners converge on is deterministic lint whose errors name the replacement. shadcn shipped exactly that in `@shadcn/lint`: six rules, **3.2k stars**, React, Svelte and Vue, and a self-reported result that "almost every task reached zero violations in one correction round" ([shadcn-ui/lint](https://github.com/shadcn-ui/lint)). shadcn's real moat is protocol, not training data. v0's design-system workflow assumes shadcn CSS variables ([v0 docs](https://v0.app/docs/design-systems)), and the shadcn MCP installs from any registry that follows its spec ([shadcn MCP](https://ui.shadcn.com/docs/mcp)).

Nexus's "Conventions are enforced, for people and agents" claim holds for token-shape errors, which is where agents trained on shadcn will go wrong first. `nx-class-conventions` fails the build on wrong prefix order, the banned `accent` token, incomplete role paths such as bare `nx:bg-primary`, raw palette colors and raw type sizes. Its messages name the fix, for example "use `nx:bg-primary-background`, not `nx:bg-blue-500`" ([nx-class-conventions.js](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/eslint-plugin-nexus/src/rules/nx-class-conventions.js)). On semantics it is stricter than shadcn's linter. It is narrower elsewhere. Arbitrary values (`nx:bg-[#2563eb]`, `nx:p-[13px]`), inline styles and per-screen restyling of components pass, and the spacing rule lints only Nexus's own token files. Getting context to the agent is the larger gap. Nexus publishes `/llms.txt` and per-page Markdown ([ai-agents.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/ai-agents.mdx#L6-L36)). That matches how coding agents fetch docs: server logs show "Claude Code out-fetched the AI retrieval bots" ([prufa.dev](https://prufa.dev/blog/agents/llms-txt-who-actually-reads-it/)). But its `/llms-full.txt` is **1.8 MB** ([nexusui.so](https://nexusui.so/llms-full.txt)), the expensive Markdown-dump pattern Indeed's benchmark ranked worst. No MCP server, skill or component manifest ships, and without a registry an agent in Cursor, v0 or Claude Code cannot install a Nexus component through the channel those tools use.

## Multi-framework teams get a shared engine and no shared components

The need for one design system across frameworks is real but held by a minority. In zeroheight's 2026 survey, design-system practitioners report **React 72%, web components 36%, Angular 28% and Vue 18%**, and **86% of design-system teams have ten or fewer people** ([zeroheight 2026](https://report.zeroheight.com/)). The demand clusters in government systems (Alberta, Ontario and Singapore ship web-component cores with framework wrappers), large enterprises, embeddable widgets and mid-migration apps. Web Awesome's framework-agnostic Kickstarter raised **$732,852 from 6,832 backers** ([BackerKit](https://www.backerkit.com/projects/fontawesome/web-awesome)). Yet a 2026 essay on framework-agnostic design systems drew 2 points on Hacker News ([HN 48225529](https://news.ycombinator.com/item?id=48225529)). Design-system leads feel the need, but it is quiet as a public conversation.

Each existing route has a documented cost. Web components still struggle with server rendering. Stencil's own team writes that "The inability to elegantly handle SSR remains one of the biggest barriers to Web Components adoption" ([Ionic](https://ionic.io/blog/the-quest-for-ssr-with-web-components-a-stencil-developers-journey)). In October 2026 Singapore's government design system measured **CLS of about 0.23 in Next.js** from un-upgraded custom elements, and the fix didn't work with Turbopack ([SGDS #899](https://github.com/GovTechSG/sgds-web-component/issues/899)). Per-framework ports lag structurally. shadcn-svelte took about **four months** to support Tailwind 4 after a request with 214 reactions ([shadcn-svelte #1643](https://github.com/huntabyte/shadcn-svelte/issues/1643)). Its issue template rejects anything that doesn't already exist upstream ([shadcn-svelte #2786](https://github.com/huntabyte/shadcn-svelte/issues/2786)). shadcn-vue users report dropped charts ([shadcn-vue #1077](https://github.com/unovue/shadcn-vue/issues/1077)). Shared headless logic moves the pain into adapters. One Ark UI user complained the Vue API is "React-shaped" ([chakra-ui/ark #4202](https://github.com/chakra-ui/ark/issues/4202)). Sharing only tokens is the budget option, and practitioners warn that separate component libraries "will inevitably end up with visual discrepancies, differing APIs, and massive maintenance overhead" ([UI Pirate](https://uipirate.com/design-systems-for-angular-react-teams-a-practical-guide)). Even IBM accepts that its web components' APIs "differ from its pure framework counterparts" ([Carbon](https://carbondesignsystem.com/developing/frameworks/web-components/)).

Nexus is honestly "framework-agnostic" at the engine and React-only above it. Its docs say another framework needs three functions, `createNexusThemeContract()`, `deriveTheme()` and `themeToCss()`, and list components under "Built per framework" ([tokens.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/foundations/tokens.mdx#L83-L106)). The FAQ calls Vue, Svelte, Angular and React Native bindings "planned" ([introduction.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/introduction.mdx#L80-L93)). A search of the tracker found no issue for them, and the open cross-platform issue says "Do not pursue cross-platform now. Two implementations of a barely-stable design system would slow us down ~3×" ([issue #218](https://github.com/nexuslabs-ai/nexus/issues/218)). The tokens are DTCG JSON, but no Style Dictionary build ships. For a React team, Nexus sidesteps every web-component complaint: light DOM, normal SSR, native form elements, no wrappers. A Vue or Angular team gets identical theme values, CI-proven contrast and a no-flash first-paint script. That beats a static token pipeline, because light and dark can't drift and runtime brand changes work anywhere. But that team builds every component and its own provider, which reproduces the drift, lag and duplicated effort the evidence describes. Nexus today is the "tokens shared" model with an unusually strong engine, not one design system across frameworks.

## An APCA-only gate wins the engineering argument and loses the compliance one

### APCA has no standing in law or procurement

APCA's standing has weakened even as tooling adopts it. It was removed from the WCAG 3 working draft in July 2023. The April 2026 Editor's Draft says only that "The contrast algorithm used in WCAG 3 is yet to be determined," and Adrian Roselli calls WCAG 3 "years away from being done" ([Roselli](https://adrianroselli.com/2026/04/wcag3-contrast-as-of-april-2026.html)). Roselli warns that advice to drop WCAG 2 in favor of APCA "would create legal risk for anyone following it." He still says "You can still use APCA," provided teams pick colors that also meet WCAG 2. Eric Eggert concludes "you cannot rely on APCA for compliance (simply because it does not exist in WCAG 2)" ([yatil.net](https://yatil.net/blog/wcag-3-is-not-ready-yet)). Every legal reference point is a WCAG 2.x version. ADA Title II cites WCAG 2.1 AA, and Section 508 cites WCAG 2.0 ([ADA Compliance Pros](https://www.adacompliancepros.com/blog/wcag-3-draft-status-procurement)). WCAG 2.2 is now ISO/IEC 40500:2025 ([Clym](https://www.clym.io/blog/wcag-2-2-iso-procurement)), and commercial buyers ask for conformance reports against WCAG 2.2 AA ([accessible.org](https://accessible.org/procurement-teams-check-acr/)). Meanwhile Chrome DevTools 149 made APCA a standard preference that "replaces the legacy AAA/AA contrast guidelines" when enabled ([Chrome for Developers](https://developer.chrome.com/blog/new-in-devtools-149)). Expect more developers to read an APCA pass as a compliance pass.

### Nexus's gate is real, and blind to WCAG 2

The library-level complaint Nexus targets is real. A 2026 audit of shadcn/ui, from a vendor that sells audits, found the default focus ring at **2.4:1**, placeholder text below 4.5:1, and a Carousel that ignores reduced motion. It framed Radix's sound behavior as undone by shadcn's styling ([thefrontkit](https://thefrontkit.com/blogs/shadcn-ui-accessibility-audit-2026)). Nexus answers that engineering complaint convincingly. It registers 116 foreground and background pairs per mode at APCA floors of Lc 75, 60 and 45 ([apca-pairs.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/apca-pairs.ts#L73-L145), [palette.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/palette.ts#L31-L35)). CI sweeps **5 surface tones × 7 brand colors × 101 contrast stops × both modes** and fails if any pair drops below its floor ([contrast.test.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/contrast.test.ts#L18-L73)). A color-blind audit also runs in CI, and focus rings are solid outlines rather than translucent box-shadows ([button.tsx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/react/src/components/button/button.tsx#L13)). APCA's least-disputed advantage, judging dark-mode text that WCAG 2 overrates, is exactly what a runtime brand engine needs.

The gate has no WCAG 2 dimension anywhere, and the test suite hides the gap. Storybook disables axe's `color-contrast` rules "so the two gates don't conflict," while every other axe rule fails the build ([preview.tsx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/react/.storybook/preview.tsx#L265-L280)). Recomputing WCAG 2 ratios from the shipped default tokens shows what a buyer's scan would see. The white label on the success badge fill, `oklch(0.62 0.2233 140)`, comes out at **3.35:1**, and on the warning fill at **3.96:1** ([nexus.css](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/tailwind/nexus.css#L348-L362), [badge.tsx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/react/src/components/badge/badge.tsx#L43-L50)). Both clear the APCA `ui` floor, and both fail WCAG 2's 4.5:1 for small text in both modes. Borders sit outside the registry. The default field border is near-black at 8.84% alpha ([nexus.css](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/tailwind/nexus.css#L325)), about **1.2:1** against white. Whether that fails SC 1.4.11's 3:1 depends on whether the border alone identifies the control. Disabled fills aren't gated either, and an open bug reports disabled primary buttons "nearly invisible in dark mode" ([issue #857](https://github.com/nexuslabs-ai/nexus/issues/857)). Nexus's docs never claim WCAG conformance, and they concede "The CI checks prove the values, not the components" ([tokens.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/foundations/tokens.mdx#L100)). But "Every text and background pair has a minimum contrast score" ([introduction.mdx](https://github.com/nexuslabs-ai/nexus/blob/61e1776/apps/docs/content/getting-started/introduction.mdx#L14-L51)) invites the APCA-instead-of-WCAG reading Roselli calls risky. No Nexus conformance report exists. Few component vendors publish one ([Level Up](https://levelup.gitconnected.com/i-wrote-a-wcag-2-2-aa-conformance-report-for-my-own-library-heres-what-a-vpat-actually-requires-1edb6f52a89e)), so one would be a differentiator, but Nexus could not truthfully fill in the contrast rows today.

### Reduced motion and forced colors

On motion and forced colors, Nexus chooses against practitioner norms on principle. Its repo rule bans `prefers-reduced-motion`, `forced-colors` and `prefers-contrast` queries so that "A component has one appearance per variant × size × theme" ([no-environment-branching.md](https://github.com/nexuslabs-ai/nexus/blob/61e1776/.claude/rules/no-environment-branching.md)). Reduced motion becomes an in-app toggle that **defaults to off** ([appearance-model.ts](https://github.com/nexuslabs-ai/nexus/blob/61e1776/packages/core/src/lib/appearance-model.ts#L140)). An earlier plan to respect the OS setting was closed as not planned ([issue #159](https://github.com/nexuslabs-ai/nexus/issues/159)). The steelman is coherent: one deterministic appearance is testable, and WCAG 2.3.3 is Level AAA and only requires that motion "can be disabled." But peers treat the OS signal as the default. Mantine says "all Mantine components which use animations support it by default" ([Mantine](https://v4.mantine.dev/hooks/use-reduced-motion/)), and WordPress and Mapbox fixed their own non-compliance as bugs ([WP Trac #62806](https://core.trac.wordpress.org/ticket/62806), [Mapbox PR #8494](https://github.com/mapbox/mapbox-gl-js/pull/8494)). A user with a vestibular disorder has already told their OS. Nexus makes them find a per-app control after the motion has played, and only if the host app exposes one. Forced colors is a smaller loss. Microsoft put high-contrast use at about **4% of Windows users** ([CSSWG minutes](https://lists.w3.org/Archives/Public/www-style/2019Apr/0004.html)). The most criticized failure, box-shadow focus rings vanishing in forced colors ([Polypane](https://polypane.app/blog/forced-colors-explained-a-practical-guide/)), doesn't apply to Nexus's outline rings. Background-only state does. The Progress component has no border, so its fill likely disappears, and the rule forbids the standard fix. No forced-colors story tests any of this.

## Conclusion

The complaint landscape splits along a line most libraries don't draw: what a theme can express, versus how component code reaches an app and stays current in it. In 2026 shadcn invested almost entirely in the second half. It added registries, diff plus agent merge, three primitive bases, a linter and an MCP server, and conceded the first half only through presets that rewrite component code. Nexus made the opposite bet, and on the first half its architecture is the better one. Restyling lives in generated tokens instead of rewrites, and a versioned engine sits beside copied components, the split shadcn itself drifted toward when it packaged `cn` and its Tailwind CSS. The catch is sequencing. In October 2026 a "better shadcn" is judged first on install, updates, primitive choice and agent reach, and Nexus has none of these yet. So the answer to "does Nexus stand as an answer" depends on the reader. A React team that runs several brands or tenants, needs runtime brand color, density and contrast safety together, and must live beside an existing MUI or shadcn app gets a yes. No other system examined assembles those pieces. For everyone else the answer is not yet, and Nexus's own docs say as much when they send single-brand apps to shadcn.

The gaps differ sharply in cost. The accessibility gaps are cheap relative to their risk. The CI matrix that already derives 3,535 themes could compute WCAG 2 ratios beside APCA, the dual gate that Roselli, Eggert and even APCA's author, through BridgePCA, point toward ([bridge-pca](https://www.npmjs.com/package/bridge-pca)). Defaulting the reduce-motion toggle to the OS preference would reverse a policy rather than add engineering. Together those changes would make the contrast claim usable as procurement evidence. The distribution gaps are expensive and partly locked in. The roadmap excludes 3-way merge, defers cross-platform work and keeps Radix as the only base, so Nexus will stay behind shadcn on the oldest copy-and-own complaint by design. With no public discussion of Nexus to test any of this against, the open question isn't whether the engine works, since the CI evidence says it does. It is whether the multi-brand, coexisting-with-legacy team that Nexus serves best is large enough to sustain it.
