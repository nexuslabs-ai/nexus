Published CSS compatibility checks

Chromium CSS fixtures, not full React component interaction tests. Light theme; common Arial font held constant to isolate the reported conflicts. Bootstrap 5.3.8, daisyUI 5.7.50, HeroUI styles 3.2.6; local Tailwind compiler 4.3.0. Existing project shadcn and Nexus CSS builds. Baseline / host + shadcn defaults / host + Nexus CSS. Bootstrap shadcn cell additionally includes generated Tailwind collapse utility; separate control recorded without it.

Conditional: generated utility, not Preflight

Bootstrap: .collapse:not(.show) { display: none; }
Tailwind: .collapse { visibility: collapse; }

With shadcn alone, panel visibility stays visible. With the generated collapse utility it becomes collapse despite display:block. Nexus stays visible. Setting visibility:visible restores it.

Token type collision

daisyUI theme: --border: 1px;
shadcn :root: --border: oklch(92.2% 0 0);
daisyUI .input: border: var(--border) solid var(--input-color, #0000);

Input border: baseline 1px / shadcn 0px / Nexus 1px. Button border: 1px / 3px / 1px. Restoring --border:1px restores both widths. Same result with stylesheet order reversed; unlayered shadcn root tokens win over layered theme defaults.

Shared token meanings collide

HeroUI: --accent: oklch(0.6204 0.195 253.83);
HeroUI: --muted: oklch(0.5517 0.0138 285.94);
shadcn: --accent: oklch(97% 0 0);
shadcn: --muted: oklch(97% 0 0);
.button--primary { --button-bg: var(--accent); --button-fg: var(--accent-foreground); }

Button becomes pale instead of blue. Helper text changes to almost-white. Radius changes 24px to 30px. Nexus preserves all three. Restoring accent, accent-foreground, muted and radius restores the measured properties. Same result with stylesheet order reversed.
