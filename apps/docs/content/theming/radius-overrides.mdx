# Radius overrides

Change the corner radius for one part of the page, or for one kind of
component.

The `corners` field (the **Corners** picker) in
[Appearance](/theming/appearance) sets the radius for the whole app.

## Set corners for an area

Add `data-radius` to a wrapper. Everything inside it uses that `corners` value:

```tsx
// components/settings-panel.tsx
import type { ReactNode } from 'react';

export function SettingsPanel({ children }: { children: ReactNode }) {
  return <div data-radius="round">{children}</div>;
}
```

`data-radius` takes the same values as `corners`: `square`, `subtle`, `smooth`,
`round` and `extra-round`.

## Round only the buttons

Set `--nx-radius-base` on a wrapper. Buttons read that variable, while inputs
and select triggers read `--nx-radius-md`, so they keep their corners:

```tsx
// components/rounded-actions.tsx
import type { CSSProperties } from 'react';

import { Button } from '@/components/button/button';
import { Input } from '@/components/input/input';
import { Select, SelectTrigger, SelectValue } from '@/components/select/select';

type RadiusStyle = CSSProperties & { '--nx-radius-base': string };
const pillButtons: RadiusStyle = { '--nx-radius-base': '9999px' };

export function RoundedActions() {
  return (
    <div data-radius="round" style={pillButtons}>
      <Button>Save changes</Button>
      <Input aria-label="Name" />
      <Select>
        <SelectTrigger aria-label="Category">
          <SelectValue placeholder="Choose a category" />
        </SelectTrigger>
      </Select>
    </div>
  );
}
```

The buttons become pills. The input and the select trigger keep the `round`
value's `12px`.

To change one button, put `style={pillButtons}` on that button instead.

`RadiusStyle` adds the custom property to the `style` type, so you don't need
to change React's global types.

## Which variable each component reads

| Variable           | Read by                                           |
| ------------------ | ------------------------------------------------- |
| `--nx-radius-base` | Button, and the start of FilterConditionField     |
| `--nx-radius-md`   | Input, InputGroup, SelectTrigger, ButtonGroupText |

`--nx-radius-base` isn't reserved for Button. Anything inside the wrapper that
uses `nx:rounded-base` picks up the override.

A component that sets its own radius, such as Carousel's arrows, keeps it. For
the rest, check the
[component source](https://github.com/nexuslabs-ai/nexus/tree/main/packages/react/src/components).

## Nested wrappers

| Inner wrapper                    | Result                                            |
| -------------------------------- | ------------------------------------------------- |
| No `data-radius` and no override | Inherits the outer override                       |
| Its own `--nx-radius-base`       | Uses its own value                                |
| Its own `data-radius`            | Resets to that value and drops the outer override |

When `data-radius` and an inline `--nx-radius-base` style are on the same
element, the inline value wins.

Overrides follow the DOM tree. A popover or menu that renders in a portal sits
outside your wrapper, so it doesn't get the override.

## Button groups

ButtonGroup squares off the edges where buttons touch. With an override, only
the outer corners are rounded. In a group that mixes Buttons with an Input or
ButtonGroupText, the two ends can have different corners.
