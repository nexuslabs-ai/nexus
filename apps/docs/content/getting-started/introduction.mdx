# Introduction

Nexus is a theme engine that ships React components, not a component library with a theme added on.

You copy the components into your app and own them. The engine, `@nexus_ds/core`, produces every token those components use, from one appearance object. Change your brand color, density or corner style, and every component follows.

## Our philosophy

Nexus rests on six ideas. Each one links to the page that explains it.

### You own the components

Every component is source code you paste into your app and edit like any other
file. To update one, paste the newer version over yours.
[Install](/getting-started/install#add-your-first-component) shows how.

### One engine makes every token

You don't write token values by hand. One function builds every color, hover
shade and dark-mode value from your appearance settings, so light and dark
can't drift apart. [Tokens](/foundations/tokens#one-engine-two-moments) shows
the pipeline.

### Every axis is a setting

Density, corners, shadows, border width, type and motion are settings, just
like color. "Make this product denser" is a one-field change, not a refactor.
[Appearance](/theming/appearance#fields) lists every field.

### Contrast is checked, not eyeballed

Every text and background pair has a minimum contrast score, and CI fails the
build when one drops below it. [Color](/foundations/color#accessibility) lists
the minimum for each pair.

### Nexus fits next to your app

Nexus CSS defines only `nx:` classes and `--nx-` variables, so your own styles
stay as they are. [Tokens](/foundations/tokens#the-nx-prefix) explains the
prefix.

### Conventions are enforced, for people and agents

ESLint rules turn Nexus conventions into build errors. See
[lint rules](/getting-started/install#optional-add-lint-rules).

Every docs page is also available as Markdown. See
[AI agents](/getting-started/ai-agents).

## Nexus and shadcn/ui

The idea that you should own your component source comes from [shadcn/ui](https://ui.shadcn.com). Nexus shares that philosophy, and we're grateful for the work that made it popular.

Both use copy-and-own components, Radix primitives, CVA for variants and `asChild` for composition. Nexus has its own theme engine, tokens and conventions:

| Concern                      | shadcn/ui                            | Nexus                                                        |
| ---------------------------- | ------------------------------------ | ------------------------------------------------------------ |
| Class names                  | `bg-primary`                         | `nx:bg-primary-background`                                   |
| Fitting into an existing app | Its theme joins your Tailwind config | Its own CSS entry, beside yours                              |
| Who writes the tokens        | You, as CSS variables in each app    | The engine, from one appearance object                       |
| What you can theme           | Color and a radius variable          | Color, density, corners, shadows, border width, type, motion |
| Hover and pressed states     | `hover:bg-primary/90`                | `nx:hover:bg-primary-background-hover`                       |
| Status colors                | `destructive`                        | `error`, `success`, `warning`, `information`                 |
| Contrast                     | The author's job                     | Checked in CI for every pair                                 |
| Conventions                  | Docs and review                      | ESLint rules that fail the build                             |

## When to use something else

Nexus pays off when you have several products, several brands, or an app that must be re-themed per customer. For a smaller project, a simpler tool may fit better:

- **One app, one theme.** A theme engine is overhead you won't get back. Use [shadcn/ui](https://ui.shadcn.com).
- **You want a large ecosystem.** Most community blocks and registries target shadcn/ui's token names.
- **You need a screen today.** Nexus asks you to adopt its token conventions first.

## FAQ

**Is Nexus a component library?**
Not in the usual sense. The components are copy-and-own source. The part you install from npm is the theme engine.

**Do I need Tailwind?**
Yes. Nexus builds its classes with Tailwind 4. Your app also needs a reset that sets `box-sizing: border-box`, such as Tailwind's Preflight or MUI's `CssBaseline`.

**Does Nexus work outside React?**
The engine does. It has no framework code, so any app can call it. The components are React only today. Vue, Svelte, Angular and React Native bindings are planned.

**Can I use the tokens in a native app?**
The tokens are DTCG JSON (the W3C design token format), so Style Dictionary can build Swift and Kotlin output. Live theme changes on native need a port of the engine.

**Can I use my own brand colors?**
Yes. Set `brandColor` to any CSS color, and Nexus builds the palette from it.
