# Install

Set up a React app with `nxds-cli`, then add any component. For a Vue app,
follow [Install by hand](#install-by-hand).

## Set up your app

```bash
npx nxds-cli@latest init
```

`init` sets up a Next.js App Router app or a Vite + React app that uses
TypeScript and React 18.3 or 19. It does every step in
[Install by hand](#install-by-hand):

| Step                | What `init` does                                                                      |
| ------------------- | ------------------------------------------------------------------------------------- |
| Tailwind 4          | Installs it, if your app doesn't have it yet                                          |
| Token CSS           | Copies it into `components/nxds/tailwind/` and adds an nxds CSS entry beside your app |
| Appearance provider | Copies it with the `cn` helper, then adds it to `app/layout.tsx` or `src/main.tsx`    |
| Packages            | Installs `@nxds/core`, `tw-animate-css`, `clsx` and `tailwind-merge`                  |
| ESLint (Vite)       | Turns off `react-refresh/only-export-components` for the nxds folder                  |

Your app's own styles stay as they are. `init` also writes `nxds.json`, which
records the nxds version and the items you installed.

If your app uses `src/`, nxds goes in `src/components/nxds/`. To choose
another folder, pass `--dir`.

## Add a component

```bash
npx nxds-cli@latest add button
```

`add` copies the component, the components it uses and the packages it needs,
from your app's nxds version. Each component page shows its `add` command.

Copied files are yours to edit. Import them from the nxds folder, such as
`components/nxds/components/button/button`.

## Update components

```bash
npx nxds-cli@latest diff
npx nxds-cli@latest update
```

`diff` lists the files that differ from the latest release. `update` moves
every installed item to it.

`update` replaces a file you haven't edited. If you edited a file, `update`
merges the release's changes into it. Line endings and trailing spaces don't
count as edits.

If you and the release changed the same lines, `update` marks them like a git
conflict. Keep the lines you want, delete the `<<<<<<<`, `=======` and
`>>>>>>>` markers, then run `update` again. If a newer release comes out
before you resolve every conflict, `update` changes no files, keeps `nxds.json`
on your release and exits `3`. To replace an edited file with the release's
copy, pass `--overwrite`.

## Use React 18

nxds runs on React 18.3 and React 19. `init` reads the React your app uses and
records it in `nxds.json`, so `add` and `update` copy the files for it.

On React 18, each component that takes a `ref` is wrapped in `forwardRef`,
because React 18 drops `ref` from a function component's props. You pass `ref`
the same way on both.

After you upgrade to React 19, run `update`:

```bash
npx nxds-cli@latest update
```

`update` switches the files to React 19 and merges the release's changes into
files you edited. Until you run it, `add` stops and `doctor` reports the
mismatch.

To install by hand on React 18, copy the files from the **React 18** tab in a
component page's Manual steps.

## Find setup problems

```bash
npx nxds-cli@latest doctor
```

`doctor` checks the provider, the CSS entry, the files, the packages and React,
and says how to fix each problem.

## Options

| Option                   | What it does                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| `--dry-run`              | Shows what would change, without changing anything                       |
| `--json`                 | Prints `{ ok, exitCode, data }`, or `{ ok, exitCode, error }` on failure |
| `--no-install`           | Skips installing npm packages                                            |
| `--cwd <path>`           | Runs in another folder                                                   |
| `--registry <url\|path>` | Installs from another registry. `NXDS_REGISTRY_URL` sets it too          |

Run `npx nxds-cli@latest --help` to list every command, or
`npx nxds-cli@latest add --help` for one command's options.

Behind a proxy, set `HTTPS_PROXY`. The CLI also reads `HTTP_PROXY` and
`NO_PROXY`.

| Exit code | Meaning                                                                                 |
| --------- | --------------------------------------------------------------------------------------- |
| `0`       | Done                                                                                    |
| `1`       | Error, such as no network or an invalid release                                         |
| `2`       | Usage error, such as an unknown option or item                                          |
| `3`       | Done, with something left for you: conflicts, kept files, manual steps or failed checks |

## Step 1: Install Tailwind 4

```bash
npm install -D tailwindcss @tailwindcss/postcss postcss
```

```js
// postcss.config.mjs
export default {
  plugins: { '@tailwindcss/postcss': {} },
};
```

Tailwind 4 builds the `nx:` classes. These steps use a new Next.js 15 App
Router app. If your app already has a UI, follow
[Add nxds to an existing app](#add-nxds-to-an-existing-app).

Remove the `@import "tailwindcss"` that `create-next-app` adds to
`globals.css`. The token CSS brings Tailwind's theme and utilities with the
`nx:` prefix. The prefix applies to the whole build, so a second import in the
same file doesn't give you unprefixed classes.

## Step 2: Add the token CSS

The token CSS defines the colors, spacing and type scale. Copy the seven files
from `packages/tailwind/` in the
[nxds repo](https://github.com/nexuslabs-ai/nxds) into
`components/nxds/tailwind/`:

```
components/nxds/tailwind/
├── nxds.css                 # entry point, imports the other six
├── variables.css
├── typography-utilities.css
├── borderwidth-utilities.css
├── border-color-aliases.css
├── motion-utilities.css
└── spacing-utilities.css
```

Install the animation utilities that some components use to open and close:

```bash
npm install tw-animate-css
```

Import Tailwind's Preflight, the token CSS and the animation utilities from your
CSS entry point:

```css
/* app/globals.css */
@layer theme, base, components, utilities;
@import 'tailwindcss/preflight.css' layer(base);
@import '../components/nxds/tailwind/nxds.css';
@import 'tw-animate-css';
```

nxds ships no reset, so the page brings Preflight. nxds components need its
`box-sizing: border-box`.

Every Tailwind class in your app now takes the `nx:` prefix: `nx:flex` works,
`flex` does not. Only nxds tokens are available, so Tailwind's default colors
are gone.
{/* audit-class-refs-ignore-next-line */}
Instead of `nx:bg-red-500`, use a token class like `nx:bg-error-background`.

To add your own tokens, put a `@theme` block in `globals.css` after the
imports. Don't edit `nxds.css`, because pasting a newer copy replaces it.

Scrollbars and form controls turn dark with the theme. Don't add a
`color-scheme` meta tag. A `light dark` meta lets the operating system darken a
light page.

## Step 3: Add the appearance provider

The provider applies the theme and saves the user's choices, like dark mode.
Its script runs in `<head>`, so the page doesn't flash the wrong theme on load.

If you use Vite, follow [Set up Vite](#set-up-vite) for this step instead.
Steps 1, 2 and 4 are the same on Vite.

Install the theme engine:

```bash
npm install @nxds/core
```

Copy the provider folder into `components/nxds/components/appearance/provider/`:

```
components/nxds/components/appearance/provider/
├── index.ts      # NxdsAppearanceProvider, useNxdsAppearance, createNxdsAppearance
├── provider.tsx
├── factory.tsx
├── script.tsx
└── server.ts     # NxdsAppearanceScript (safe to import on the server)
```

Set your app's starting theme. Copy the default appearance and change the
fields you want:

```ts
// app/appearance-state.ts
import { DEFAULT_NXDS_APPEARANCE, type NxdsAppearanceState } from '@nxds/core';

export const defaultAppearance = {
  ...DEFAULT_NXDS_APPEARANCE,
  brandColor: '#2563eb',
  surfaceTone: 'slate',
} satisfies NxdsAppearanceState;
```

`brandColor` sets the primary color. `surfaceTone` sets the gray used for
backgrounds. For every field, see [Appearance](/theming/appearance).

Add the script and the provider to your root layout:

```tsx
// app/layout.tsx
import { NxdsAppearanceProvider } from '@/components/nxds/components/appearance/provider';
import { NxdsAppearanceScript } from '@/components/nxds/components/appearance/provider/server';

import { defaultAppearance } from './appearance-state';

import './globals.css';

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <NxdsAppearanceScript
          storageKey="app-appearance"
          defaultState={defaultAppearance}
        />
      </head>
      <body className="nx:bg-background nx:text-foreground nx:typography-body-default">
        <NxdsAppearanceProvider
          storageKey="app-appearance"
          defaultState={defaultAppearance}
        >
          {children}
        </NxdsAppearanceProvider>
      </body>
    </html>
  );
}
```

`nx:typography-body-default` gives page text the nxds font and size, which
follow the appearance settings.

Give the script and the provider the same `storageKey`. The provider saves the
user's choices under that key, and the script reads them on the next load.

To render the saved theme on the server, see
[Load the theme from a cookie](#optional-load-the-theme-from-a-cookie).

## Step 4: Add the `cn` helper


To check dark mode, add a toggle that uses `useNxdsAppearance`:

```tsx
// components/mode-toggle.tsx
'use client';

import { useNxdsAppearance } from '@/components/nxds/components/appearance/provider';
import { Button } from '@/components/nxds/components/button/button';

export function ModeToggle() {
  const { state, setState, resolvedMode } = useNxdsAppearance();

  const toggle = () =>
    setState({ ...state, mode: resolvedMode === 'dark' ? 'light' : 'dark' });

  return <Button onClick={toggle}>Mode: {resolvedMode}</Button>;
}
```

`resolvedMode` is the mode on screen, so the toggle also works when `mode` is
`'system'`.

## Check your setup

- [ ] `nxds.css` is imported from your CSS entry point
- [ ] The provider wraps your app, and the script is in `<head>`
- [ ] Reloading in dark mode doesn't flash light first
- [ ] The mode you pick is still set after a full reload

If the button has no styles, `nxds.css` isn't imported (step 2). If it stays
light when you toggle, the provider isn't wrapping it (step 3).

If the page flashes on reload, check that the script and the provider use the
same `storageKey`. With different keys, they load different themes.

## Set up Vite

On Vite, this section replaces step 3. Install `@nxds/core`, copy the
provider into `src/components/nxds/components/appearance/provider/`, and create
`src/appearance-state.ts` as in step 3.

Vite doesn't render on the server, so add the theme script to `index.html` at
build time:

```ts
// vite.config.ts
import {
  createNxdsAppearanceBootstrapScript,
  createNxdsAppearanceSnapshotFromState,
} from '@nxds/core';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

import { defaultAppearance } from './src/appearance-state';

const STORAGE_KEY = 'app-appearance';
const defaultSnapshot =
  createNxdsAppearanceSnapshotFromState(defaultAppearance);

export default defineConfig({
  plugins: [
    react(),
    {
      name: 'nxds-appearance-bootstrap',
      transformIndexHtml(html) {
        const script = createNxdsAppearanceBootstrapScript({
          storageKey: STORAGE_KEY,
          defaultSnapshot,
        });
        return html.replace('</head>', `<script>${script}</script></head>`);
      },
    },
  ],
});
```

Wrap your app in the provider, with the same storage key:

```tsx
// src/main.tsx
import { createRoot } from 'react-dom/client';

import App from './App';
import { defaultAppearance } from './appearance-state';
import { createNxdsAppearance } from './components/nxds/components/appearance/provider';

import './index.css';

const { NxdsAppearanceProvider } = createNxdsAppearance({
  storageKey: 'app-appearance',
  defaultState: defaultAppearance,
});

createRoot(document.getElementById('root')!).render(
  <NxdsAppearanceProvider>
    <App />
  </NxdsAppearanceProvider>
);
```

Don't apply the theme in a `useEffect`. Effects run after the first paint, so
the page would flash the default theme first.

## (Optional) Load the theme from a cookie

On Next.js, read the user's saved theme from a cookie. The server then renders
the right theme on the first request. Replace the layout from step 3 with this
one:

```tsx
// app/layout.tsx
import {
  createNxdsAppearanceSnapshotFromCookie,
  DEFAULT_COOKIE_KEY,
} from '@nxds/core';
import { cookies } from 'next/headers';

import { NxdsAppearanceProvider } from '@/components/nxds/components/appearance/provider';
import { NxdsAppearanceScript } from '@/components/nxds/components/appearance/provider/server';

import { defaultAppearance } from './appearance-state';

import './globals.css';

export default async function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const cookieStore = await cookies();
  const snapshot = createNxdsAppearanceSnapshotFromCookie(
    cookieStore.get(DEFAULT_COOKIE_KEY)?.value,
    defaultAppearance
  );

  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <NxdsAppearanceScript
          storageKey="app-appearance"
          defaultState={snapshot.state}
        />
      </head>
      <body className="nx:bg-background nx:text-foreground nx:typography-body-default">
        <NxdsAppearanceProvider
          storageKey="app-appearance"
          cookieWriteKey={DEFAULT_COOKIE_KEY}
          defaultState={snapshot.state}
        >
          {children}
        </NxdsAppearanceProvider>
      </body>
    </html>
  );
}
```

If the cookie is missing or invalid, `createNxdsAppearanceSnapshotFromCookie`
falls back to `defaultAppearance`.

If you read the cookie in the root layout, Next.js renders every route on each
request.

The provider saves the theme in two places:

| Prop             | Saves to       | Read by                                               |
| ---------------- | -------------- | ----------------------------------------------------- |
| `cookieWriteKey` | A cookie       | The server, on the next request                       |
| `storageKey`     | `localStorage` | The head script before first paint, then the provider |

When both are set, `localStorage` wins in the browser. To use only the cookie,
set `storageKey={false}` on both the script and the provider.

If your app uses a strict Content Security Policy, pass a nonce:
`<NxdsAppearanceScript nonce={nonce} />`.

## Add nxds to an existing app

nxds CSS defines only `nx:` classes and `--nx-*` variables, so your app's
styles stay as they are. Follow steps 1 to 4 with these three changes:

1. **Give nxds its own CSS entry** and import it after your own stylesheet:

   ```css
   /* app/nxds.css */
   @import '../components/nxds/tailwind/nxds.css';
   @import 'tw-animate-css';
   ```

   Your `globals.css` keeps its `@import "tailwindcss"`. Two files make two
   Tailwind builds, one prefixed and one not.

2. **Keep your app's reset.** nxds needs `box-sizing: border-box`. Tailwind's
   Preflight, MUI's `CssBaseline` and Bootstrap's Reboot all set it. If your app
   has no Tailwind, install it for the nxds entry.
3. **Add the provider and the script** as in step 3. nxds and your theme share
   the `.dark` class on `<html>`.

Three global effects remain:

| Source                | What it adds                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `.dark`               | `color-scheme: dark`, so your scrollbars and form controls turn dark in dark mode                 |
| `tw-animate-css`      | `enter`, `exit`, `accordion-*`, `collapsible-*` and `caret-blink` keyframes, as in any shadcn app |
| Tailwind's own output | `spin`, `ping`, `pulse` and `bounce` keyframes and `--tw-*` properties, as in any Tailwind 4 app  |

Style an nxds component with `nx:` classes. An unprefixed class loses to the
component's own `nx:` class, because nxds's stylesheet loads later.

Your content inside an nxds component inherits its text color, font and line
height.

If your design system is a package, ship the nxds CSS entry from it and end
the entry with `@source './';`. Tailwind skips `node_modules`, so without that
line the package's classes are never generated.

nxds overlays use three layers:

| Variable               | Default | Used by                         |
| ---------------------- | ------- | ------------------------------- |
| `--nx-z-index-modal`   | 50      | Dialog, Sheet, Drawer           |
| `--nx-z-index-popover` | 70      | Popover, Select, menus, Tooltip |
| `--nx-z-index-toast`   | 100     | Toaster                         |

If your app's layers sit higher, like MUI's dialogs at 1300, raise these on
`:root`.

An open nxds dialog blocks pointer events outside itself. Render another
library's popups inside it, such as an MUI `Menu` with `disablePortal`.

[Examples](/getting-started/examples) shows nxds added to a shadcn app, an MUI
app and a company package.

The nxds ESLint rules keep copied components following nxds conventions:

```js
// eslint.config.mjs
import { nxdsComponentConfig } from '@nxds/eslint-plugin/config';

const eslintConfig = [
  // ...your existing config
  {
    files: ['components/**/*.tsx'],

  },

```

`nxdsComponentConfig` turns on three rules for the files you list:

| Rule                             | Catches                                                                           |
| -------------------------------- | --------------------------------------------------------------------------------- |
| `nx-class-conventions`           | Wrong prefix order, removed tokens, incomplete token names and raw palette colors |

`next/core-web-vitals`. If your config has none, install `typescript-eslint` and
add `languageOptions: { parser: tseslint.parser }` to the entry.

## Step 3: Add the appearance plugin

The plugin applies the theme and saves the user's choices, like dark mode. A
script in `index.html` applies the saved theme before the first paint.

Install the theme engine and the Vue component dependencies:

```bash
npm install @nxds/core reka-ui @vueuse/core
```

Copy `packages/vue/src/components/appearance/` into
`src/components/appearance/`.

Set your app's starting theme:

```ts
// src/appearance-state.ts
import { DEFAULT_NXDS_APPEARANCE, type NxdsAppearanceState } from '@nxds/core';

export const defaultAppearance = {
  ...DEFAULT_NXDS_APPEARANCE,
  brandColor: '#2563eb',
} satisfies NxdsAppearanceState;
```

Add Tailwind, the `@` import alias and the theme script to `vite.config.ts`:

```ts
// vite.config.ts
import {
  createNxdsAppearanceBootstrapScript,
  createNxdsAppearanceSnapshotFromState,
} from '@nxds/core';
import tailwindcss from '@tailwindcss/vite';
import vue from '@vitejs/plugin-vue';
import { fileURLToPath, URL } from 'node:url';
import { defineConfig } from 'vite';

import { defaultAppearance } from './src/appearance-state';

const defaultSnapshot =
  createNxdsAppearanceSnapshotFromState(defaultAppearance);

export default defineConfig({
  plugins: [
    vue(),
    tailwindcss(),
    {
      name: 'nxds-appearance-bootstrap',
      transformIndexHtml(html) {
        const script = createNxdsAppearanceBootstrapScript({
          storageKey: 'app-appearance',
          defaultSnapshot,
        });
        return html.replace('</head>', `<script>${script}</script></head>`);
      },
    },
  ],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
});
```

Install the plugin with the same storage key:

```ts
// src/main.ts
import { createApp } from 'vue';

import App from './App.vue';
import { defaultAppearance } from './appearance-state';
import { createNxdsAppearance } from './components/appearance';

import './style.css';

createApp(App)
  .use(
    createNxdsAppearance({
      storageKey: 'app-appearance',
      defaultState: defaultAppearance,
    })
  )
  .mount('#app');
```

Give the page the nxds background, text color and font in `index.html`:

```html
<body
  class="nx:bg-background nx:text-foreground nx:typography-body-default"
></body>
```
