# Install

Set up your app once, then copy in any Nexus component.

Copied components are your files: edit them freely, and paste a newer version
to update.

## Step 1: Install Tailwind 4

```bash
npm install -D tailwindcss @tailwindcss/postcss postcss
```

```js
// postcss.config.mjs
export default {
  plugins: { '@tailwindcss/postcss': {} },
};
```

Tailwind 4 builds the `nx:` classes. These steps use a Next.js 15 App Router
app.

Remove any `@import "tailwindcss"` from your CSS, including the one
`create-next-app` adds to `globals.css`. The token CSS imports Tailwind for
you, with the `nx:` prefix. A second import duplicates Tailwind's base styles
and can bring back its default colors.

## Step 2: Add the token CSS

The token CSS defines the colors, spacing and type scale. Copy the seven files
from `packages/tailwind/` in the
[Nexus repo](https://github.com/nexuslabs-ai/nexus) into `styles/nexus/`:

```
styles/nexus/
├── nexus.css                 # entry point, imports the other six
├── variables.css
├── typography-utilities.css
├── borderwidth-utilities.css
├── border-color-aliases.css
├── motion-utilities.css
└── spacing-utilities.css
```

Install the animation utilities that some components use to open and close:

```bash
npm install tw-animate-css
```

Import both from your CSS entry point:

```css
/* app/globals.css */
@import '../styles/nexus/nexus.css';
@import 'tw-animate-css';
```

Every Tailwind class in your app now takes the `nx:` prefix: `nx:flex` works,
`flex` does not. Only Nexus tokens are available, so Tailwind's default colors
are gone.
{/* audit-class-refs-ignore-next-line */}
Instead of `nx:bg-red-500`, use a token class like `nx:bg-error-background`.

To add your own tokens, put a `@theme` block in `globals.css` after the
imports. Don't edit `nexus.css`, because pasting a newer copy replaces it.

If your app already uses unprefixed Tailwind classes, this setup won't work
with them.

Then tell the browser the app supports both color schemes, so scrollbars and
form controls match the theme:

```tsx
// app/layout.tsx (step 3 completes this file)
import type { Viewport } from 'next';

export const viewport: Viewport = { colorScheme: 'light dark' };
```

Outside Next.js, add `<meta name="color-scheme" content="light dark" />` to
your `<head>`.

## Step 3: Add the appearance provider

The provider applies the theme and saves the user's choices, like dark mode.
Its script runs in `<head>`, so the page doesn't flash the wrong theme on load.

If you use Vite, follow [Theme setup](/getting-started/theme-setup#vite) for
this step instead. Steps 1, 2 and 4 are the same on Vite.

Install the theme engine:

```bash
npm install @nexus_ds/core
```

Copy the provider folder into `components/appearance/provider/`:

```
components/appearance/provider/
├── index.ts      # NexusAppearanceProvider, useNexusAppearance, createNexusAppearance
├── provider.tsx
├── factory.tsx
├── script.tsx
└── server.ts     # NexusAppearanceScript (safe to import on the server)
```

Add the script and the provider to your root layout:

```tsx
// app/layout.tsx
import { DEFAULT_NEXUS_APPEARANCE } from '@nexus_ds/core';
import type { Viewport } from 'next';

import { NexusAppearanceProvider } from '@/components/appearance/provider';
import { NexusAppearanceScript } from '@/components/appearance/provider/server';

import './globals.css';

export const viewport: Viewport = { colorScheme: 'light dark' };

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <NexusAppearanceScript
          storageKey="app-appearance"
          defaultState={DEFAULT_NEXUS_APPEARANCE}
        />
      </head>
      <body className="nx:bg-background nx:text-foreground">
        <NexusAppearanceProvider
          storageKey="app-appearance"
          defaultState={DEFAULT_NEXUS_APPEARANCE}
        >
          {children}
        </NexusAppearanceProvider>
      </body>
    </html>
  );
}
```

Give the script and the provider the same `storageKey`. The provider saves the
user's choices under that key, and the script reads them on the next load.

To change the starting theme, see [Theme setup](/getting-started/theme-setup).

## Step 4: Add the `cn` helper

```bash
npm install clsx tailwind-merge
```

Copy `packages/react/src/lib/utils.ts` to `lib/utils.ts`.

`cn` merges class names and resolves conflicts between `nx:` classes. That's
what lets `<Button className="nx:bg-error-background" />` replace the button's
own background.

## Add your first component

Each component lists the packages to install and the files to copy. Copy the
files in the order shown. For Button:

<InstallBlock slugs={['button']} />

Paths are relative to `packages/react/src/` in the repo. Keep the same folder
structure under your `@/` import alias, and the imports between files work without
edits. If a component has its own stylesheet, like Progress, it also lists the
`@import` lines to add to `app/globals.css`.

Render it:

<ComponentDemo id="button/default" />

To check dark mode, add a toggle that uses `useNexusAppearance`:

```tsx
// components/mode-toggle.tsx
'use client';

import { useNexusAppearance } from '@/components/appearance/provider';
import { Button } from '@/components/button/button';

export function ModeToggle() {
  const { state, setState, resolvedMode } = useNexusAppearance();

  const toggle = () =>
    setState({ ...state, mode: resolvedMode === 'dark' ? 'light' : 'dark' });

  return <Button onClick={toggle}>Mode: {resolvedMode}</Button>;
}
```

`resolvedMode` is the mode on screen, so the toggle also works when `mode` is
`'system'`.

If the button has no styles, `nexus.css` isn't imported (step 2). If it stays
light when you toggle, the provider isn't wrapping it (step 3).

## (Optional) Add lint rules

The Nexus ESLint rules keep copied components following Nexus conventions:

```bash
npm install -D @nexus_ds/eslint-plugin
```

```js
// eslint.config.mjs
import { nexusComponentConfig } from '@nexus_ds/eslint-plugin/config';

const eslintConfig = [
  // ...your existing config
  {
    files: ['components/**/*.tsx'],
    ...nexusComponentConfig(),
  },
];

export default eslintConfig;
```

This turns on `nx-class-conventions`, `no-render-prop-types` and
`no-multi-statement-jsx-handler` for the files you list.

The rules need a TypeScript parser. `create-next-app` sets one up through
`next/core-web-vitals`. If your config has none, install `typescript-eslint` and
add `languageOptions: { parser: tseslint.parser }` to the entry.

## Where the files are

Every file you copy comes from the
[Nexus repo](https://github.com/nexuslabs-ai/nexus):

| File                | Path in the repo                                     |
| ------------------- | ---------------------------------------------------- |
| Token CSS           | `packages/tailwind/*.css`                            |
| Appearance provider | `packages/react/src/components/appearance/provider/` |
| `cn` helper         | `packages/react/src/lib/utils.ts`                    |
| Components          | `packages/react/src/components/{name}/`              |

## Fork the whole design system

If you want the whole design system in your own monorepo, skip this page. Clone
the repo, run `pnpm install`, then run `pnpm export --name=your-design-system`
and follow the generated scaffold.
