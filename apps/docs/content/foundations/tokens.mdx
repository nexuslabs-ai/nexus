# Tokens

Tokens are the named values every Nexus component uses for color, spacing,
radius, shadows, borders and motion.

[Open the Token lab](/playground/tokens) to browse every token in the current theme.

## Token layers

| Layer     | What it is                    | Example                               |
| --------- | ----------------------------- | ------------------------------------- |
| Primitive | A raw value                   | `--nx-color-blue-500`, a spacing step |
| Semantic  | A role that points at a value | `--nx-color-primary-background`       |
| Utility   | The class a component uses    | `nx:bg-primary-background`            |

Components use semantic tokens through utilities. A component that uses a
primitive color fails the Nexus lint rules.

## The `nx:` prefix

Every Nexus class starts with `nx:`, and every Nexus variable starts with
`--nx-`. Nexus CSS defines nothing else, so it fits beside your own styles.

The prefix comes before every modifier:

| Write                                  | Not                                    |
| -------------------------------------- | -------------------------------------- |
| `nx:hover:bg-primary-background-hover` | `hover:nx:bg-primary-background-hover` |
| `nx:md:flex`                           | `md:nx:flex`                           |
| `nx:[&>svg]:text-foreground`           | `[&>svg]:nx:text-foreground`           |

## Semantic names

A semantic name is a family, then a role, then an optional state:

| Part   | Values                                                                          |
| ------ | ------------------------------------------------------------------------------- |
| Family | `primary`, `secondary`, `error`, `success`, `warning`, `information`            |
| Role   | `background`, `foreground`, `border`, `subtle`, `subtle-foreground`, `disabled` |
| State  | `hover`, `active`                                                               |

Not every family has every role. The Token lab lists the ones that exist.

The primary button reads `nx:bg-primary-background`, then
`nx:hover:bg-primary-background-hover` and
`nx:active:bg-primary-background-active`. Every state has its own token,
so there are no opacity modifiers like `bg-primary/90`.

Surfaces follow the same pattern:

| Surface          | Token        | Hover token        |
| ---------------- | ------------ | ------------------ |
| Page             | `background` | `background-hover` |
| Card, panel, row | `container`  | `container-hover`  |
| Popover, menu    | `popover`    | `popover-hover`    |

The name always ends in a role. `nx:bg-primary` resolves to nothing.

## One engine, two moments

`deriveTheme()` in `@nxds/core` produces every color token. It runs once
at build time to write the default colors into `nexus.css`. It runs again in
the browser whenever the appearance changes.

Same function, same inputs, same output. The page looks right with JavaScript
off, and a live theme change needs no rebuild.

Spacing, radius, shadow, border and motion come straight from DTCG JSON (the
W3C design token format). `nexus.css` holds every density, corner, shadow and
border option, and the provider picks one with a data attribute. The
appearance state is the object described in [Appearance](/theming/appearance).

Light and dark come from the same call, so dark mode can't drift from light.

## Other frameworks

The engine has no framework or DOM code. Another framework needs three
functions:

- `createNexusThemeContract()` turns the appearance state into the engine's
  input.
- `deriveTheme()` returns the light and dark color token maps.
- `themeToCss()` turns those maps into CSS.

An app that styles itself without CSS, like a React Native app, reads the
color token map and the DTCG files directly. Every framework gets the same
values, so a React app and a Vue app in one product render the same gray.

| Concern          | Shared by every framework                                       | Built per framework                                     |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------- |
| Token values     | Every axis: color, spacing, radius, shadow, border, motion      | Nothing                                                 |
| Contrast         | The CI checks prove the values, not the components              | Nothing                                                 |
| Appearance model | State shape, validation, snapshots, first-paint script          | Nothing                                                 |
| Token source     | DTCG JSON, readable by Style Dictionary, Swift and Kotlin tools | A build target                                          |
| State binding    | None                                                            | A provider or store in the framework's own style        |
| Components       | Variants, data attributes, sizing and focus rules               | Components built on the framework's headless primitives |

The Nexus components are React.
